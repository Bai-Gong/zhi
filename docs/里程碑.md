## 阶段总览

## M1 · 查看阅读 MVP（本次交付）

**范围**：打开即读——渲染、缩放、翻页、缩略图/书签侧栏、首页工具中心与最近文件。模块边界见技术方案第 4 节（5 模块并行）。

**明确不做**（推至 M2+）：全文搜索、批注高亮、阅读模式、多标签、任何写文件操作。

### 验收标准

参考机型：验收用 Windows 开发机（Windows 11 + WebView2 evergreen，≥4 核 / 8GB 内存）；下文所有性能类判据均指该机型。

工程与命令级：

1. `npm run tauri dev` 一键启动，控制台无 pdf.js worker 报错（无「fake worker」主线程回退告警）。
2. `npm run tauri build` 成功出安装包；**安装后**以下功能用例全部复验通过（重点验证 CSP 与 asset 协议在产物形态可用）。
3. `npm run build`（纯前端构建）零错误。

功能用例（手工逐条）：

4. 首页点「打开文件」选择 PDF → 进入查看器并渲染第 1 页；支持中文文件名与含空格的深层路径。
5. 打开 ≥500 页、≥20MB 的 PDF：拖动滚动条全程往返一趟，DOM 中画布数量始终 ≤ 可视页数+2（虚拟化生效）；每次停止滚动后 ≤1 秒内当前视口页完成渲染（无持续白屏或错版）；任务管理器观察 WebView2 渲染进程私有内存：完整往返两趟，第二趟结束读数较第一趟结束读数增长 ≤15%，超出判不通过。
6. 缩放：工具栏按钮、Ctrl+滚轮、适应宽度三种方式可用，范围 25%–400%；快速连续缩放不出现旧尺寸画面覆盖新画面（竞态）；缩放后视口停留在原锚点附近。
7. 翻页：页码输入跳转、PageUp/PageDown、缩略图点击跳页、书签节点点击跳页均正确；滚动时页码指示与实际可视页一致。
8. 缩略图页签：懒渲染（滚动到才生成）、当前页高亮跟随滚动；书签页签：多级树可折叠展开、跳页准确；无书签的文档该页签禁用并有空态提示。
9. 侧栏可折叠/展开，折叠后查看器宽度自适应重排。
10. 打开损坏/加密 PDF：不崩溃，给出可读的中文错误提示与「重新选择文件」入口。
11. 最近文件：打开过 3 个文件后重启应用，列表保留且顺序为最近优先；点击条目直接打开；已不存在的文件显示失效态且不崩溃（可移除条目）。
12. 窗口从默认 1280×860 缩至配置的最小尺寸 960×600（技术方案 6.2 节 `minWidth`/`minHeight`）过程中布局不破；深浅色跟随系统（M1 只需不破版，深色阅读模式属 M2）。

## M2 · 阅读增强

> 执行计划（设计走查 + 施工分解）：[M2-计划.md](M2-计划.md)。

**范围**：全文搜索、批注高亮（查看与新建）、阅读模式（沉浸全屏 + 深色）、键盘快捷键体系、多标签文档。

**技术要点**：core/document 预构建逐页文本索引（`getTextContent` + 坐标，映射命中→矩形）；高亮以覆盖层呈现，「保存」经 pdf-lib 画半透明矩形写入**副本**（不动原文件）；深色模式经 CSS 变量反转 UI（文档画布可选反色滤镜）。

**验收标准**：

1. 参考机型上，500 页纯文本 PDF 全文搜索 ≤5 秒返回完整结果列表（含页码与上下文摘录）且进度可见，超时判不通过；点击结果跳页并滚动到命中位置、高亮闪烁标识。
2. 大小写敏感/不敏感开关、当前页/全文档范围开关生效。
3. 鼠标选中文本 →「高亮」着色正确贴合选中行；多色高亮；「另存副本」后用 Chrome/Acrobat 打开可见同样的高亮。
4. 沉浸模式隐藏侧栏与工具栏（鼠标移到边缘唤出）；深色模式下 UI 全部组件正常、文字对比度可读。
5. 快捷键清单（打开/关闭/搜索/缩放/翻页/阅读模式）全部生效且不与系统冲突。
6. 多标签：同时打开 3 个文档可切换，各标签独立保持页码与缩放；关闭标签释放对应文档内存。

## M3 · 页面组织

**范围**：组织页面视图（缩略图网格）、拖拽重排、单页/多选旋转、删除、提取，另存副本。

**技术要点**：pdf-lib `copyPages` 生成新文档（页序/旋转写入副本）；组织视图为独立全屏模式，缩略图渲染**消费 core/document 暴露的缩略图服务**（与侧栏同一来源，不复制渲染实现，符合技术方案 4.3 边界规则 1：pdfjs-dist 只在 core 内 import）。

**验收标准**：

1. 进入组织视图显示全部页面网格缩略图，支持 HTML5 拖拽重排，实时反映顺序。
2. 多选（Ctrl/框选）后旋转 90°/180° 即时生效；删除有确认与撤销（本次会话内）。
3. 提取所选页生成新 PDF：页数、顺序、朝向正确。
4. 「另存副本」（plugin-dialog + plugin-fs）后，用 Chrome 与 Acrobat 打开：页序/朝向/书签导航均正确，中文内容无乱码。
5. 所有操作只写用户指定的新文件，原文件字节不被修改（对比哈希验证）。

## M4 · 合并拆分

**范围**：合并向导（多文件、顺序调整、可选页码范围）、拆分（按页码范围/每 N 页/按顶级书签）、**工具向导页框架**（选文件→配置→执行→导出，后续工具复用）。

**验收标准**：

1. 合并 3 个共 100MB 的 PDF 成功，进度可见；结果页序与配置一致，页内链接/书签保留或按策略降级（明确提示）。
2. 指定页码范围合并（如 1.pdf 取 1-3、2.pdf 取 5,8）结果正确。
3. 拆分按「每 N 页」与「按书签」各生成多文件，命名规则可预期（`原名_1.pdf`…）。
4. 向导四步流转完整：可回退、执行中可取消、失败给出原因并保留已选配置。
5. 向导框架抽为可复用组件（shell 归档），M6 的新工具以配置方式接入而无需改框架代码。

## M5 · 基础编辑

**范围**：编辑模式——文本覆盖编辑（遮盖原文本 + 重写）、图片增删改（覆盖/替换/移动/缩放）、选中对象属性面板（字体/字号/颜色/位置）。

**技术要点（诚实定位）**：纯 JS 生态无完整重排引擎，编辑采用「覆盖补丁」模型：原文以无衬底矩形遮盖，新文本用 pdf-lib 标准字体或 `public/fonts/` 内置中文字体子集嵌入；编辑态在内存对象模型上操作，导出时经 pdf-lib 落盘。

**验收标准**：

1. 双击文本进入编辑：修改一行中文文本后导出，Acrobat 打开可读、可再选中复制，无缺字（字体嵌入验证）。
2. 插入/替换/删除图片（png/jpg），移动与等比缩放跟手，导出后位置与显示正确。
3. 属性面板随选中对象联动，修改即时预览。
4. 撤销/重做（≥20 步）覆盖文本与图片全部操作。
5. 导出为副本，原文件不被修改。

## M6 · 格式转换

**范围**：PDF→图片（png/jpg，逐页/批量打包）、图片→PDF、PDF→Word（.docx，文本型）、Word→PDF（.docx，基础版式）。（打印不在本阶段，见「后置能力」。）

**技术要点**：出图走 pdf.js 渲染 canvas→Blob；PDF→Word 用 docx 包按阅读顺序重建段落（版式有损）；Word→PDF 走 mammoth→HTML→自研分页 DOM→html2canvas-pro 截图→pdf-lib 成册。全部依托已冻结依赖。

**验收标准**：

1. 100 页 PDF 导出 png（可选 96/192 dpi）：张数正确、清晰度符合所选 dpi、文件名带页码；批量导出有进度与取消。
2. 10 张图片合成 PDF：顺序可调、可设页面大小与边距。
3. 文本型 PDF→Word：段落数量与顺序正确、表格降级为文本不丢失内容；用 Office/WPS 打开无修复提示。
4. Word→PDF：标题/正文/图片/简单表格保留，中文字体不缺字；复杂版式（艺术字、文本框）允许降级，产品内明确提示「基础版式转换」。

## 后置能力（超出必备范围，需新依赖/新决策，逐项另立方案）

OCR（Tesseract 前端 wasm 或原生）、表单填写与制作、电子签名、安全（加密/水印/脱敏）、压缩（qpdf 类原生处理）、文档对比、AI 问答、**打印**（各平台打印对话框/静默打印需原生侧配合；macOS WKWebView 下 `window.print()` 不可用属 Tauri 已知平台差异——知识判断，本机无 macOS 未实测；与「MVP 零自研 Rust 命令」冲突，故移出 M6，产品分析必备清单本无打印）。触发即按集群变更流程评审依赖与架构。

## 阶段推进原则

- 每阶段开始前，在该阶段目录内做一次设计走查，冲突回改《技术方案.md》对应章节，两文档与代码同仓演进。
- 每阶段验收在 `qa` 分支执行通过后合回 `main`（遵循 AGENTS.md 分支约定）。
- 任何阶段都不得修改依赖清单（package.json / Cargo.toml）；确有必要时先在技术方案第 3 节提变更评审。

# 百工·纸（Zhi）技术方案

> 依据：[产品分析.md](产品分析.md)、集群 [AGENTS.md](../../AGENTS.md)。
> 本文所有第三方版本号均为 **2026-10-19 经 `npm view`（npmmirror registry）实测的最新版**；pdfjs-dist 的包内文件布局经 tarball 解包实测。

## 1. 约束与总体原则

- 技术栈锁定（集群约定，不可更改）：**Tauri 2 + React + TypeScript + Vite**，包管理器 **npm**。
- 分支/身份遵循 AGENTS.md：`zhi/` 仓库已有 `main`/`develop`/`qa` 三分支与本地 `user.name/user.email` 配置（已实测确认），日常开发在 `develop`。
- **MVP 阶段 Rust 侧保持轻量**：只通过 Tauri 2 官方插件做文件对话框、文件读取、系统打开与日志，**不写自研 Rust 命令、不引入原生 PDF 引擎**。全部 PDF 处理在前端完成。
- **依赖一次性冻结**：第 3 节清单在脚手架阶段一次装完，之后不改 `package.json` / `Cargo.toml`（产品分析「必备核心能力」范围内已全覆盖；「可后置能力」如需新依赖属新变更，另行决策）。
- 不引入测试框架与 UI 组件库：M1 验收以《里程碑.md》的手工用例清单为准；界面自绘（CSS 变量 + 自有组件），为日后接入 `fang/` 共享外壳留接口。

## 2. PDF 引擎选型：前端为主，Rust 为辅

### 2.1 结论

| 职责 | 引擎 | 说明 |
| --- | --- | --- |
| 渲染 / 文本层 / 书签 / 搜索索引 / 缩略图 | **pdfjs-dist**（Mozilla pdf.js） | 前端 Canvas 渲染，worker 线程解析；Acrobat 级阅读体验的事实标准 |
| 页面组织 / 合并拆分 / 编辑覆盖 / 另存 | **pdf-lib** | 纯 JS 的 PDF 结构读写（复制页、旋转、删除、画矩形/文本/图片、嵌入字体） |
| PDF→Word | pdfjs-dist 文本抽取 + **docx** | 按阅读顺序重建段落，生成 `.docx`（版式有损，符合「基础转换」定位） |
| Word→PDF | **mammoth**（docx→HTML）+ 自研分页 DOM + **html2canvas-pro**（截图）+ pdf-lib（成册） | 纯前端链路，覆盖基础版式 |
| PDF↔图片 | pdfjs-dist（渲染出图）+ pdf-lib（图片成册） | 无需额外依赖 |
| 文件对话框 / 读取兜底 / 系统打开 / 日志 | Tauri 2 官方插件（Rust 侧） | 见 2.3 |

一句话方案：**pdfjs-dist@6 前端渲染，Rust 侧只做文件对话与读取等基础命令。**

### 2.2 为什么 Rust 侧不做 PDF 引擎（pdfium / mupdf 绑定）

- 渲染交互（选区、高亮、跟随缩放的文本层）发生在 DOM/Canvas，原生引擎渲染需整页位图过 IPC 传给前端，缩放/滚动时传输与内存开销大、体验差。
- pdfium/mupdf 的 Rust 绑定引入 C/C++ 构建链，Windows/macOS 双端构建复杂度显著上升，与「MVP 轻量」矛盾。
- 产品分析的全部**必备核心能力**均可由 pdfjs-dist + pdf-lib + 转换三件套覆盖；真正需要原生性能的 OCR/压缩在「可后置」清单里，届时再评估（属新变更）。

### 2.3 Rust 侧形态（MVP）

`src-tauri/src/lib.rs` 仅注册插件，无自研命令：

```rust
tauri::Builder::default()
    .plugin(tauri_plugin_opener::init())
    .plugin(tauri_plugin_dialog::init())
    .plugin(tauri_plugin_fs::init())
    .plugin(tauri_plugin_log::Builder::new().build())
    .run(tauri::generate_context!())
    .expect("error while running zhi");
```

- **主路径（读文件）**：不走 IPC 传字节。用 `@tauri-apps/api/core` 的 `convertFileSrc(path)` 把本地路径转成 asset 协议 URL，pdf.js 直接 `fetch` 流式加载（零拷贝、支持大文件）。需在 `tauri.conf.json` 启用 asset 协议（见 6.2）。
- **兜底路径**：asset 协议异常时用 `@tauri-apps/plugin-fs` 的 `readFile` 读 `Uint8Array` → `getDocument({ data })`。两条路径收敛在 `src/core/document` 同一接口后面，上层无感。
- **预案（不属于 MVP）**：若未来大文件 IPC 成为瓶颈，再增加自研 `read` 命令以 `tauri::ipc::Response` 返回二进制。

### 4.3 并行开发的边界规则（代码评审按此检查）

1. **`pdfjs-dist`、`pdf-lib` 等重库只允许在 `src/core/document` 内 import**。查看器与侧栏拿到的是 core 暴露的类型与函数（`openDocument` / `renderPage` / `getOutline` / store），杜绝 worker 重复初始化与 API 散用。**整页渲染与缩略图渲染同源**：一切 pdf.js 绘制（含 M3 组织视图的缩略图网格）都必须经 core 暴露的渲染/缩略图接口，sidebar 等模块只是消费方，不得自建渲染实现。
2. 模块之间不互相 import 组件：`viewer` 与 `sidebar` 互不依赖，均只消费 core 的 store 与接口；页面组装只在 `shell` 的路由层完成。
3. `src/main.tsx`、`src/App.tsx`、`src/styles/`、`src/components/` 由模块 1 独占写权限，其余模块只读引用。
4. 每个模块内部自行组织子目录（如 `viewer/pages/`、`viewer/toolbar/`），但不得在自身目录外建文件。
5. zustand store 定义在 `core/document`（文档会话）与 `shell`（UI 偏好）两处，其他模块不得新建全局 store。

## 5. 核心数据流：打开文件 → 渲染 → 翻页/缩放

### 5.1 打开文件

1. 用户在首页或查看器点「打开」→ `core/document` 调 `@tauri-apps/plugin-dialog` 的 `open({ filters: [{ name: 'PDF', extensions: ['pdf'] }] })`，得到绝对路径。
2. 写入最近文件：localStorage（键 `zhi.recentFiles`，去重置顶，上限 20 条，存路径/文件名/时间/页数）。
3. `convertFileSrc(path)`（`@tauri-apps/api/core`）把路径转为 asset 协议 URL，路由跳 `/viewer?path=<encoded>`。
4. `core/document` 懒初始化 pdf.js worker（见 6.1），`getDocument({ url })` 装载 → `PDFDocumentProxy` 存入 zustand store；同时读 `numPages`、各页尺寸、`getOutline()` 书签树。失败（损坏/加密）→ store 错误态，UI 给出明确提示；asset URL 失败自动走 `plugin-fs.readFile` 兜底（2.3）。

### 5.2 渲染（连续滚动 + 虚拟化）

5. `viewer` 订阅 store；滚动容器只保留可视页 ±1 页的占位（每页占位高度按页尺寸×缩放预估），IntersectionObserver 报告进入视口的页。
6. 对每张需要显示的页：core 的渲染队列按「可视页优先」串行派发 `page.render({ canvasContext, viewport })`；同一画布的新任务先 `renderTask.cancel()` 旧任务，配合递增 generation token，只有最新一代允许上屏（防竞态串页）。
7. Canvas 物理分辨率 = `viewport(scale) × devicePixelRatio`，CSS 尺寸 = `viewport(scale)`；单边光栅上限 8192px（Chromium canvas 上限 16384，留余量），超限自动封顶该页缩放。
8. 文本层（TextLayer）与画布使用同一 viewport 构建，保证选中位置与渲染像素对齐（M2 搜索/高亮的地基）。

### 5.3 翻页与缩放

9. 翻页：滚动 → IntersectionObserver 报告当前页 → `store.currentPage` 更新 → 侧栏缩略图高亮同步；页码输入、方向键、缩略图/书签点击 → 目标页 `scrollIntoView`。
10. 缩放：Ctrl+滚轮 / 工具栏按钮 / 适应宽度 → 更新 `store.scale`（0.25–4.0，1.1^n 档位）→ 可视页按新尺寸重排并重渲染，滚动位置按「当前页顶部锚点」补偿，避免缩放后视口跳飞。

## 6. 关键配置（施工直接照抄）

### 6.1 pdf.js worker 初始化（`src/core/document/pdfjs.ts`，全应用唯一入口）

实测依据：pdfjs-dist@6.4.299 包内确认存在 `legacy/build/pdf.mjs`、`legacy/build/pdf.worker.min.mjs` 等文件，且类型文件含 `GlobalWorkerOptions.workerSrc/workerPort`。**默认用 legacy 构建**（对旧 WebView 的 JS 内置特性如 `Promise.withResolvers` 兼容，体积代价可忽略）：

```ts
import * as pdfjsLib from 'pdfjs-dist/legacy/build/pdf.mjs';
// 方案 A（推荐）：Vite 打包为 worker chunk
import PdfjsWorker from 'pdfjs-dist/legacy/build/pdf.worker.min.mjs?worker';

let inited = false;
export function initPdfjs() {
  if (inited) return;
  pdfjsLib.GlobalWorkerOptions.workerPort = new PdfjsWorker();
  inited = true;
}
export { pdfjsLib };
```

若 `?worker` 在当前 Vite 版本异常，替换为方案 B（只改这一行语义）：

```ts
import workerUrl from 'pdfjs-dist/legacy/build/pdf.worker.min.mjs?url';
pdfjsLib.GlobalWorkerOptions.workerSrc = workerUrl;
```

### 6.2 `vite.config.ts` 与 `tauri.conf.json` 要点

```ts
// vite.config.ts
export default defineConfig({
  plugins: [react()],
  clearScreen: false,
  server: { port: 1420, strictPort: true },
  build: { target: 'esnext', chunkSizeWarningLimit: 2000 },
  optimizeDeps: { exclude: ['pdfjs-dist'] }, // dev 预打包已知会捣乱，排除
});
```

```jsonc
// tauri.conf.json（节选）
{
  "productName": "百工纸",
  "identifier": "com.baigong.zhi",
  "app": {
    "windows": [{ "title": "百工·纸", "width": 1280, "height": 860, "minWidth": 960, "minHeight": 600 }],
    "security": {
      "assetProtocol": {
        "enable": true,
        "scope": ["**"]            // 本地单机工具，允许打开任意用户文件
      },
      "csp": {
        "default-src": "'self' asset: http://asset.localhost https://asset.localhost blob: data:",
        "script-src": "'self'",
        "worker-src": "'self' blob:",
        "style-src": "'self' 'unsafe-inline'"
      }
    }
  }
}
```

注意：CSP 在 `tauri dev` 下默认不生效，**必须以 `tauri build` 产物实测**（M1 验收项）；Windows 平台 asset 协议主机是 `http(s)://asset.localhost`，macOS/Linux 是 `asset://`，csp 两种都写上。

## 7. 关键风险与对策

| # | 风险 | 对策 |
| --- | --- | --- |
| 1 | **pdf.js worker 在 Vite/Tauri 下加载失败**（最常见的坑：dev 预打包、产物 CSP 拦 worker、跨源限制） | 6.1 固定为唯一初始化点 + `?worker` 方案；6.2 的 `optimizeDeps.exclude` 与 `worker-src 'self' blob:`。症状识别：若 worker 构造失败，pdf.js 会退回主线程伪 worker（可用但滚动卡、控制台告警）——出现即回查 CSP 与 worker 配置。dev（localhost:1420）与产物（自定义协议）均为同源，无跨源问题 |
| 2 | 主构建需要较新 JS 内置特性，旧 WebView 崩 | 默认走 legacy 入口（一行 import 之差，已实测包内存在）；Windows WebView2 evergreen 自动更新无此忧，主要保护 macOS 存量系统 |
| 3 | asset 协议未启用/作用域不符 → 打开文件 404 | `tauri.conf.json` 按式启用；core 内自动兜底 `plugin-fs.readFile`；**兜底前置条件**：capabilities 授予 `fs:allow-read-file` 并配 `"**"` scope（`fs:default` 只覆盖应用专属目录，缺此授权兜底必现 forbidden path，见 8.2）；中文/空格路径由协议层处理，无需手写编码 |
| 4 | 大 PDF（数百页/上百 MB）内存膨胀、滚动掉帧 | 虚拟化只保留可视±1 页；离屏页 `page.cleanup()`；光栅 8192px 封顶；worker 解析不占主线程 |
| 5 | 缩放/滚动风暴下渲染竞态（旧结果覆盖新画面、串页） | renderTask.cancel + generation token（5.2 第 6 条）；渲染队列串行化 |

| 7 | pdf-lib 维护节奏慢（1.17.1） | 已知风险；若遇缺陷，备选 fork `@cantoo/pdf-lib`（API 兼容），替换属依赖变更需评审——先在案记录 |

## 8. 脚手架落地步骤（施工方执行）

1. `zhi/` 已有 README 与 docs，create-tauri-app 不能直接在非空目录初始化：在旁生成临时目录 `npm create tauri-app@latest zhi-tmp -- --template react-ts --manager npm`，将生成物（除 README 外）并入 `zhi/`，README 保留现有内容按需合并；随后删除临时目录。
2. 按第 3.1 节命令一次性安装 npm 依赖；按 3.2 节在 `src-tauri/Cargo.toml` 增加四个插件，`lib.rs` 按 2.3 节注册。
3. **capabilities 授权**（`src-tauri/capabilities/default.json`）。注意：`fs:default` 只覆盖应用专属目录（AppData 等），**读写经对话框选定的任意路径必须显式授权 `fs:allow-read-file` / `fs:allow-write-file` 并配 scope**——权限本身不附带作用域，缺 scope 时运行时报 forbidden path（Tauri 2 官方文档，tauri.app/plugin/file-system）：

   ```json
   {
     "$schema": "../gen/schemas/desktop-schema.json",
     "identifier": "default",
     "windows": ["main"],
     "permissions": [
       "dialog:default",
       "opener:default",
       "log:default",
       "fs:default",
       { "identifier": "fs:allow-read-file", "allow": [{ "path": "**" }] },
       { "identifier": "fs:allow-write-file", "allow": [{ "path": "**" }] }
     ]
   }
   ```

   说明：`dialog:default` 覆盖打开/保存对话框（插件本身不触碰文件系统，无需路径 scope）；`opener:default` 已含 `allow-reveal-item-in-dir`，「在资源管理器中显示」无需额外授权；`log:default` 含 `allow-log`，JS 端日志必需；`fs` 的 `"**"` scope 与 asset 协议 scope（6.2 节）一致，供 plugin-fs 兜底读取（2.3 节）与 M3 起「另存副本」写入共用。本地单机工具，作用域放宽风险可控（与 6.2 节 asset scope 同一决策）。
4. 按第 6 节写入 `vite.config.ts`、`tauri.conf.json`、`src/core/document/pdfjs.ts`，再按第 4 节建目录骨架。
5. 在 `develop` 分支提交；验收按《里程碑.md》M1 清单执行。
